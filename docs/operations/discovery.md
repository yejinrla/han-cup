# 발견 홈 운영

## 인기 집계 활성화

기존 한컵 Supabase 프로젝트의 SQL Editor에서 `supabase/migrations/007_home_popularity.sql` 전체를 실행한다. 기존 데이터·후기를 삭제하지 않는 추가 마이그레이션이며 재실행 가능하다. 기존 익명/로그인 후기 RLS는 바꾸지 않는다. 코드 배포만 되고 함수가 아직 없으면 홈은 인기 집계 준비 중을 표시한다.

함수 `public.popular_drinks()`는 최근 24시간의 공개·비공개 기록을 음료별 작성 사용자 수로 집계한다. 같은 사용자의 반복 기록은 한 명, 숨김 기록·판매 종료 음료·미래 작성 시각은 제외한다. 반환은 최대6개의 drink_id/recorders뿐이다. 비공개 별점과 내용·닉네임·작성자 ID·개별 시각은 반환하지 않는다. 공개 평균 별점은 기존대로 공개 후기만 사용한다.

홈 방문 시 최신 집계를 읽고, 열려 있는 화면은 5분마다 갱신한다. 숨긴 탭에서는 중단하고 복귀 시 갱신한다. 갱신 오류가 나면 마지막 정상 결과와 지연 안내를 유지한다. API `/api/discovery/popular`와 개인화된 홈은 공유 캐시하지 않는다. 삭제는 DB 집계에 즉시 반영되지만 이미 열려 있는 화면에는 다음 갱신까지 최대5분 걸릴 수 있다.

## 신메뉴 검수 등록

`data/catalog/new-arrivals.json`은 검수된 신메뉴만 담는 배열이다. 초기 파일은 비어 있다. 최근 DB 등록 제품이나 정보 확인일을 신메뉴 출시일로 추정하지 않는다.

1. 브랜드 공식 자료에서 음료·출시일·영양정보를 확인한다. 새 음료라면 기존 catalog 검수 발행 절차로 먼저 DB에 등록한다.
2. 각 항목의 `drinkId`에 실제 제품 UUID, `releasedOn`에 공식 출시일(YYYY-MM-DD), `sourceUrl`에 같은 브랜드의 HTTPS 공식 출시 자료 URL을 입력한다.
3. 검수 후 커밋·배포한다. 활성 제품이며 기본 변형이 있고 미래 출시가 아닌 항목만 최신 출시순 최대6개 표시된다. 같은 제품은 하나로 합친다. 타 브랜드/비공식 출처, 잘못된 날짜, 등록되지 않은 제품은 표시하지 않는다.
4. 종료한 신메뉴는 배열에서 제거한다. 이 파일은 카탈로그 제품 자체를 삭제하지 않는다.

실제 인기와 신메뉴가 없으면 빈 상태를 표시하며 임의 순위나 가상 메뉴로 채우지 않는다.
