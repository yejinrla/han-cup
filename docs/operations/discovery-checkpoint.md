# 홈·검색 분리 작업 체크포인트

사용량 제한으로 중단된 작업을 재구현하지 않고 보존한 상태다. 이 커밋은 작업 저장용이며 전체 기능 완료 선언이 아니다.

## 구현되어 있는 내용
- `/` 발견 홈과 `/search` 전체 음료 검색 분리, 검색·필터·정렬·비교 유지 및 기존 홈 검색 URL 리다이렉트.
- 홈/검색/주변 매장/좋아요/나의 한컵 5개 하단 탭.
- 검수된 신메뉴 등록 구조. `data/catalog/new-arrivals.json`은 아직 빈 배열이며 신메뉴를 임의로 생성하지 않았다.
- 최근24시간 공개·비공개 기록의 음료별 고유 작성자 수 집계 RPC와 API. 반복 작성자는 중복 제외, 숨김 기록·판매 종료·미래 작성 시각 제외. 익명 응답에 비공개 원문·작성자 ID를 반환하지 않는다.
- 5분 갱신/포커스·가시성 처리 코드, 오류 시 이전 결과 유지 코드.
- 기록 폼·개인정보 안내의 통계 포함 고지와 운영 문서.

## 이번 재확인 결과
- `npm run lint`: 통과.
- `npm run typecheck`: 통과.
- `npm test`: 35개 통과 (실제 폐기용 로컬 PostgreSQL 테스트 포함).
- `npm run build`: 통과.
- `npx playwright test tests/e2e/discovery.spec.ts`: 2개 통과, 1개 실패.
- 실패: `popularity refreshes every five minutes and keeps last results when refresh fails`. 가상 시계를 5분 전진시킨 뒤 예상한 `3명이 기록`이 보이지 않는다. 실제 타이머/수화 시점/테스트 환경 중 무엇이 원인인지 미확정이며 해결되지 않았다.
- 이전 검증에서 실제 세션 브라우저 테스트5개는 통과했다. 이번 체크포인트에서는 다시 실행하지 않았다.
- 독립 리뷰는 사용량 제한으로 중단되었으며 완료되지 않았다.

## 남은 작업
1. 실패한 갱신 테스트를 재현하고 원인을 확인해 수정한다. 테스트를 삭제하거나 성공으로 표시하지 않는다.
2. 전체 익명/실제 세션 브라우저 검증과 독립 리뷰를 마친다.
3. 운영 Supabase SQL Editor에 `supabase/migrations/007_home_popularity.sql`을 실행한다. 아직 운영에는 적용하지 않았다. 함수가 없으면 홈은 집계 준비 중으로 표시된다.
4. 공식 출시 정보 검수 후 실제 신메뉴를 등록한다.
5. 운영 홈·검색 UI와 집계 결과를 확인한다.

## 함께 보존한 이전 설정 파일
`supabase/setup.sql`과 `supabase/initial-catalog.sql`은 초기 서비스 연결 때 작성한 파일이다. 새 프로젝트/빈 카탈로그용이며 기존 운영 프로젝트에 초기 설정 SQL을 다시 실행하지 않는다. 새 인기 기능을 활성화할 때는 007 마이그레이션만 사용한다.
