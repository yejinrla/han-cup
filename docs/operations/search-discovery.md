# 검색 탐색 화면 운영

기본 `/search`는 최근 검색어, 급상승 검색어, 추천 검색어, 최근 본 음료를 표시한다. 검색 또는 필터 선택 시 기존 검색 결과로 전환한다. 전체 목록은 `/search?all=1`이다.

## 배포 후 DB 설정

Supabase SQL Editor에서 `supabase/migrations/010_search_discovery.sql` 전체를 실행한다. 반복 실행 가능하다. 운영 DB 적용 여부는 아직 확인되지 않았다. 기존 서버 전용 `SUPABASE_SERVICE_ROLE_KEY`가 있어야 검색 신호를 기록한다. 이 키를 브라우저 환경변수나 채팅에 공개하지 않는다.

미적용 시 검색과 개인 기록은 동작하고 급상승 영역은 준비 상태를 표시한다. 적용 후 `/api/search/activity` GET의 `available:true`를 확인한다. 빈 목록은 오류가 아니라 집계 기준 미달일 수 있다.

## 집계 기준

공개 카탈로그의 음료명·브랜드명 및 검증된 추천 키워드만 집계한다. 임의 검색 문장은 전송하지 않는다. 최근 24시간과 직전 24시간을 비교해 최근 신호 3개 이상이고 증가량이 양수인 키워드 최대 5개를 표시한다. 같은 주소·키워드는 UTC 날짜별 한 번, 같은 일일 해시는 30개 키워드까지 기록한다. 신호 수는 고유 사용자 수가 아니다.

주소는 서버에서 일일 HMAC 해시로 바뀌며 원문 주소나 계정 ID를 저장하지 않는다. 원본 테이블과 쓰기 함수는 서버 역할만 접근하고 공개 API는 집계만 반환한다. 48시간이 지난 신호는 다음 기록 요청에서 삭제한다. 정기 작업에 의한 즉시 삭제는 아니다.

최근 검색어 10개와 최근 본 음료 12개는 브라우저에만 저장하며 최근 30일 항목만 표시한다. 각 영역에서 전체 삭제할 수 있다. 저장소 접근이 차단되어도 검색은 가능하다. 개인 기록 삭제는 계정과 연결되지 않은 집계에 영향을 주지 않는다.
