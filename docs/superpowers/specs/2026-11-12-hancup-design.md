# 한컵(HanCup) MVP 설계 초안

작성일: 2026-11-12 (한국 시간). 상태: 사용자 승인 완료(2026-11-12). 구현 계획도 승인되어 로컬 MVP를 구현·검증했다. 외부 계정 연결과 공개 배포는 별도 출시 게이트다.

## 1. 의도와 성공 기준

여러 카페 브랜드의 음료 정보를 한곳에서 탐색하고, 원하는 음료를 판매하는 브랜드와 주변 매장을 찾고, 영양정보·가격으로 비교하고, 마신 경험을 다시 확인하는 반응형 웹서비스다. 다양한 카페 음료를 즐기고 새로운 음료를 발견하려는 사람을 대상으로 한다. 음료 도감의 감성은 별도의 게임·수집 시스템이 아니라 UI로 표현한다.

초기 성공 기준: 사용자가 로그인 없이 음료를 찾고 필터링하여 최대 3개를 비교한 뒤 주변 브랜드 매장으로 이동할 수 있다. 로그인하면 찜과 반복 음용 기록을 관리한다. 비공개 기록이 다른 사용자에게 노출되거나, 미제공 영양정보가 0으로 표시되는 것은 실패다.

## 2. 사용자가 결정한 범위

- Next.js, TypeScript, 모바일을 우선 고려한 반응형 웹. 개인 프로젝트로 실제 배포까지 진행.
- 브랜드: 스타벅스, 투썸플레이스, 이디야, 메가MGC커피, 컴포즈커피, 빽다방.
- 대표 음료로 출시한 뒤 확장. 브랜드별 20~30종은 제안된 초기 목표로, 확정된 출시 의무 수량은 아니다.
- 음료명·브랜드 검색, 칼로리·당류·카페인 상한 필터.
- 한 잔 기준 영양정보, 용량 표시, 100ml 기준 전환. 가격 비교 포함.
- 최대 3개 음료 비교: 가격, 용량, 칼로리, 당류, 카페인, 공개 평균 평점.
- 공개·비공개 후기: 별점, 글, 마신 날짜. 같은 음료를 여러 번 기록 가능.
- 평균 평점에는 사용자별 최신 공개 별점 한 개만 반영.
- 후기 사진 업로드 없음. 사진은 음료 목록·상세에만 사용. 사용 가능한 사진이 없으면 공통 일러스트.
- 찜 및 내 찜 목록.
- 탐색·비교·공개 후기 열람·매장 찾기는 비로그인 가능. 기록 작성과 개인 공간은 카카오 로그인 필요.
- 한컵 내부의 지도·매장 목록, 카카오맵 길찾기 연결. 현재 위치 또는 지역명 검색.
- 브랜드의 주변 매장을 안내하며 매장별 실제 판매·재고를 보장하지 않음.
- 공식 자료 수집 보조 + 사람 검수 후 공개. 출처·확인일 관리.
- 초기 무료 운영. 유료 서비스 가입·자동 과금은 범위 밖.
- UI는 C안: 차분한 초록색, 중립적인 밝은 배경, 음료 이미지 카드, 영양정보를 함께 읽는 구성.

## 3. 접근 대안과 선택

### 서비스 구조

1. Next.js + 관리형 백엔드: 인증·DB 운영 부담이 낮고 빠르게 출시할 수 있으나 제공 업체 제약을 받는다.
2. Next.js + 별도 백엔드: 제어 범위가 넓으나 서버 개발·운영 부담이 크다.

사용자는 1번을 선택했다. 구체적인 제공 업체는 아래 작성자의 제안이며 아직 사용자가 별도로 확정한 사항은 아니다.

### 데이터 관리

수동 입력은 단순하지만 반복 작업이 많다. 완전 자동 갱신은 오류가 즉시 공개될 위험과 사이트별 유지 비용이 크다. 선택한 방식은 수집 결과를 임시 저장하고 검수한 변경만 발행하는 혼합 방식이다. 초기에는 파일 기반 수집·검수·가져오기로도 충족한다.

### 시각적 방향

A는 이미지와 감성, B는 수치와 검색, C는 이미지 카드와 핵심 수치의 균형을 강조했다. 사용자는 C를 선택했다. 시안은 scratch/hancup-visual-directions.html에 있으며 예시 제품·수치·일러스트를 사용한 임시 자료다.

## 4. MVP 경험과 화면

### 음료 도감

음료명·브랜드 검색과 브랜드·음료 분류·HOT/ICE 필터, 영양 상한 필터. 카드에는 제품 이미지 또는 일러스트, 브랜드, 음료명, 기준 사이즈·온도·용량, 핵심 영양 수치, 가격, 공개 평점·참여자 수, 찜과 비교 동작을 둔다. 작은 화면에서는 정보 우선순위를 조정한다.

작성자 제안: 기본은 한 잔 기준, 초기 정렬은 이름순으로 안정적으로 제공. 가격·칼로리·당류·카페인순 정렬을 제공한다. 누락값은 정렬 마지막에 둔다. 필터와 비교는 현재 표시 기준에 따른다. 기준을 바꾸면 숫자와 단위를 명확히 갱신하고 기존 상한값은 초기화하여 의도치 않은 조건 변환을 피한다. 정보 없는 항목에 상한이 걸리면 그 음료는 제외한다. 검색 결과 0건에서는 조건 초기화를 안내한다. 검색·필터를 URL로 유지한다.

### 상세와 비교

상세: 기본 정보, 제공되는 사이즈·온도 선택, 핵심 영양정보와 추가 공식 성분, 가격, 원문 출처·확인일, 찜, 비교 추가, 주변 브랜드 매장, 공개 후기.

각 사이즈·온도는 별도 변형이다. 공식 수치가 있는 변형만 선택 가능하다. 기본 사이즈를 초기 선택하고, 다른 사이즈의 영양정보를 단순 용량 배수로 추정하지 않는다. 100ml 환산은 공식 제공량과 영양 수치의 기준이 일치하는 경우에만 계산한다. 단순 컵 최대 용량만 있고 영양정보의 실제 제공량과 대응이 불명확하면 환산하지 않는다. 환산값은 계산값임을 밝히고, 가격과 평점은 100ml 전환으로 환산하지 않는다.

비교 선택은 2~3개로 비교 화면을 구성하며 최대 초과 시 교체를 안내한다. 같은 제품의 다른 변형 비교도 허용하는 것을 작성자 기본안으로 한다. 모바일은 가로 스크롤 표와 항목명을 고정하여 읽도록 한다. 로그인 없이 비교 선택을 유지한다.

### 후기와 내 공간

작성자 기본안: 1~5점 정수 별점 필수, 글은 선택(최대 1,000자), 마신 날짜는 한국 시간 오늘을 기본값으로 두며 미래 날짜는 허용하지 않는다. 공개 여부는 작성할 때 선택하고 기본값은 비공개. 제품 단위로 기록하고 마신 변형은 선택적으로 연결한다. 초기에는 샷·시럽 등 커스텀 영양정보 계산을 하지 않는다.

내 공간은 찜과 마신 기록을 구분하고 최신 마신 날짜순으로 정렬한다. 본인 기록 수정·삭제·공개 전환을 지원한다. 공개 후기에는 서비스 내 닉네임을 사용하고 카카오 계정 식별자·이메일은 노출하지 않는다. 공개 후기 목록은 기록별로 노출하되 평균은 사용자별 한 표다.

집계 규칙: 제품마다 삭제·운영 숨김되지 않은 공개 기록 중 사용자별 생성 시점이 가장 최근인 기록을 선택한다. 마신 날짜 수정은 최신 순서를 바꾸지 않는다. 선택된 별점의 산술평균을 소수점 한 자리로 표시하고 참여 사용자 수도 표시한다. 최신 공개 기록을 비공개 전환·삭제하면 그 사용자의 다음 최신 공개 기록으로 대체한다. 공개 기록이 없으면 그 사용자 표를 제거한다. 비공개 기록을 새로 써도 이전 공개 평점을 덮지 않는다. 집계 대상 0명은 ‘평가 없음’이며 0점으로 표현하지 않는다.

작성자 제안: 공개 후기 신고와 운영자 숨김 기능을 최소 운영 범위에 둔다. 숨김 기록은 공개 노출·평균에서 제외하되 작성자는 상태를 확인할 수 있다. 댓글·팔로우·좋아요·별도 피드는 제외한다. 계정 탈퇴 시 본인 기록·찜·프로필을 삭제하고 평점을 재집계한다.

### 주변 매장

음료에서 진입하면 해당 브랜드로 제한. 현재 위치는 사용자가 요청한 순간에만 권한을 요청하고 서버에 영구 저장하지 않는다. 거부·실패 시 지역명 검색. 브랜드 이름을 사용해 카카오 장소 검색 결과를 조회하고 관련 브랜드 카페 결과를 지도·목록에 표시한다. 매장명, 주소, 제공되는 연락처, 계산 가능한 거리와 카카오맵 연결을 표시한다. 실시간 메뉴·재고나 영업 중 여부는 추정하지 않는다. 매장별 판매가 다를 수 있음을 짧게 안내한다. 검색 결과는 서비스 자체의 전체 매장 DB로 복제하지 않는다. API 실패·무료 쿼터 소진 시 일시 이용 불가 안내와 외부 카카오맵 검색 연결을 제공한다.

## 5. 데이터와 운영

브랜드, 제품, 변형(온도·사이즈), 변형별 영양·가격과 출처, 사용자 프로필, 후기, 찜, 신고, 운영 권한을 분리한다. 영양·가격은 null과 0을 구분한다. 공식 가격이 없으면 미제공. 매장별 가격을 대표 가격으로 임의 승격하지 않는다.

작성자 제안: MVP는 6개 브랜드별 대표 제품을 수동 선정한다. 커피·티·에이드·스무디 등 범주를 포함하고, HOT/ICE 변형은 별도 제품 수로 부풀리지 않는다. 시즌 여부와 판매 확인 상태, 확인일을 관리한다. 공식 메뉴에서 사라져도 즉시 삭제하지 않고 검수 후 판매 종료 처리한다. 종료 제품은 기본 탐색에서 제외하지만 기존 기록과 찜에서는 보존하고 종료 상태를 표시한다.

수집 과정은 원문 확인 → 후보 데이터 → 형식·단위·기준량·중복 검증 → 사람 검수 → 묶음 발행 순서다. 발행 전후 이력을 보존해 잘못된 변경을 되돌릴 수 있게 한다. 주 1회 확인을 운영 기본 제안으로 하되 자동 갱신 보장은 하지 않는다. 사이트 접근·자동 수집 정책을 확인하며 차단을 우회하지 않는다. 초기에는 전용 관리자 UI 대신 검수 파일과 제한된 운영 도구로 운영할 수 있다.

공식 공개 방식 조사 결과: 스타벅스는 핵심 영양 항목, 이디야·메가·빽다방은 핵심 항목과 용량이 확인됐다. 모든 제품·변형의 확보를 보장한 결과는 아니다. 투썸·컴포즈는 조사 도구 403으로 확인이 보류됐다. 이 두 브랜드의 공식 자료 경로 확보는 6개 브랜드 출시 전 필요한 작업이다. 공식 근거를 확보하지 못한 영양정보는 추정하지 않는다. 제품 사진은 사용 가능한 범위를 확인하고 확보한 것만 쓰며, 나머지는 자체 공통 일러스트로 대체한다.

## 6. 기술 구성 — 작성자 제안

- Next.js App Router + TypeScript. 모바일 우선 반응형. 상세·목록은 검색엔진이 읽을 수 있도록 서버 렌더링을 활용한다.
- Supabase Free의 PostgreSQL과 Auth. 카카오 OAuth를 연결한다. 소셜 계정 이메일이 없어도 식별 가능한 인증 구성을 검토하여 불필요한 이메일 수집을 피한다.
- 공개 제품 데이터와 개인 기록의 DB 접근 규칙을 분리. 비공개 후기는 소유자만 읽고 수정하며, 공개 후기 집계와 캐시는 비공개 원문을 포함하지 않는다. 공개→비공개 변경 후 노출과 집계가 즉시 일관되게 갱신되게 한다. 운영자 권한은 사용자 수정 가능한 프로필 필드로 부여하지 않는다.
- Vercel Hobby로 개인·비상업 프로젝트 배포를 제안. 상업화 시 배포 요금·이용 조건 재검토. 무료 제공 도메인을 사용하고 유료 도메인은 제외.
- 음료 이미지는 소수의 최적화된 정적 자산부터 시작. 후기 업로드·별도 사진 업로드 파이프라인은 불필요.
- Kakao Maps JavaScript SDK + 장소 검색. REST 비밀키는 서버에서 사용하고 브라우저용 키는 허용 도메인을 설정한다. 캐시·저장 범위는 API 이용 조건에 맞춘다.
- 수집·검수 작업은 웹 요청 처리와 분리한 수동 실행 작업으로 시작. 초기 예약 인프라를 의무화하지 않는다.

무료는 사용량 제한 내 시작한다는 뜻이다. Supabase Free의 비활성 프로젝트 일시 중지와 저장·전송 제한을 고려하고, 무료 백업 제공을 가정하지 않아 별도 내보내기 절차를 둔다. 카카오맵 무료 적용은 개발자 계정의 앱 활성화 순서와 현재 정책에 좌우되므로 실제 앱에서 확인한다. 무료 혜택 미적용이면 임의 유료 전환하지 않고 사용자와 대안을 정한다. 각 공급자의 사용량을 확인하고 유료 초과 사용은 활성화하지 않는다.

## 7. 추후 확장 / 제외

추후: 전체 메뉴·추가 브랜드 확대, 개인화 추천, 커스텀 옵션 기록·영양 계산, 알림, 수집 자동화 확대, 정교한 운영 화면.

MVP 제외: 후기 사진 업로드, 매장별 재고·판매 보장, 주문·결제, 자체 길찾기, 네이티브 앱, 게임형 수집 보상, 댓글·팔로우, AI 추천.

## 8. 검증과 출시 조건

- 핵심 여정: 비로그인 검색 → 복합 영양필터 → 3개 비교 → 상세 → 주변 매장, 카카오 로그인 → 찜 → 반복 기록 → 개인 목록.
- 비공개 기록 접근 차단(다른 계정·비로그인·집계·캐시 포함), 공개 전환·삭제·운영 숨김에 따른 평점 갱신.
- 단위·미제공·실제 0·100ml 환산 및 환산 불가 케이스 검증.
- 모바일 탐색·비교 가독성, 키보드 탐색, 이미지 대체 텍스트, 로딩·빈 결과·오류·권한 거부 처리.
- 실제 공식 자료의 제품·변형 대응을 표본 점검하고 출처·확인일 표시. 6개 브랜드 모두 공식 근거 자료를 확보한 범위에서 등록.
- 실제 카카오 로그인·지도 앱 설정과 무료 이용 가능성 확인. 외부 계정 생성·연결 및 배포는 구현 후 별도 실제 설정 단계이며 이 문서 작성으로 수행하지 않는다.

## 9. 구현자에게 맡기는 사항

세부 컴포넌트·스타일 도구, 검색 쿼리 최적화, 테이블·파일 이름, 입력 제한 구현, 데이터 검수 파일 형식, 공급자 설정 절차는 위 동작과 무료 제약을 지키는 범위에서 구현자가 결정한다. 반대로 브랜드 수·후기 공개 규칙·사진 업로드 제외·무료 우선·C안은 임의로 바꾸지 않는다.
