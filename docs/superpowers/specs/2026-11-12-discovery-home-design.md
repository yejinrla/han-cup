# 발견 홈과 음료 검색 분리

## 목적
홈에서는 새 음료와 지금 한컵 사용자들이 많이 기록하는 음료를 발견한다. 전체 음료 탐색·영양정보 필터는 독립된 검색 탭에서 사용한다. 기존 480px 앱 화면을 유지한다.

## 화면과 탐색
- 하단 탭: 홈 / 검색 / 주변 매장 / 좋아요 / 나의 한컵.
- 홈(/): 간결한 소개, 검색 바로가기, 신메뉴, 지금 많이 기록하는 음료 섹션. 각 음료는 기존 상세로 연결하고 좋아요·비교 기능을 유지한다.
- 검색(/search): 현재 도감의 전체 목록·이름/브랜드 검색·종류/온도/영양 필터·정렬·페이지 이동을 보존한다.
- 기존 검색 조건이 붙은 홈 URL은 새 검색 화면으로 옮겨 기존 공유 링크가 동작하도록 한다. 상세·비교에서 전체 목록으로 돌아가는 링크도 검색을 향한다.

## 신메뉴
사용자가 선택한 방식은 공식 출시 정보를 확인한 메뉴를 운영자가 직접 선정·등록하는 것이다. 제품 ID, 공식 출시일, 출처를 검수해 관리한다. DB 등록일이나 정보 확인일을 출시일로 추정하지 않는다. 검증된 신메뉴가 아직 없으면 준비 중 안내와 전체 음료 탐색 링크를 표시한다. 실제 신메뉴 검수·데이터 등록은 화면 구현과 구분한다.

## 인기 기준
- 최근 24시간 내 작성된 음료 기록을 기준으로 집계한다. 마신 날짜나 수정 시각으로 계산하지 않는다.
- 공개와 나만 보기 기록을 모두 포함한다. 같은 사용자의 같은 음료 반복 기록은 1명으로 집계한다.
- 운영 숨김 처리된 기록과 판매 종료 음료는 제외한다.
- 5분마다 갱신하며 홈 제목은 '지금 많이 기록하는 음료'로 표시한다. 판매량 순위나 완전한 즉시 반영으로 표현하지 않는다.
- 동률이면 최근 기록 시각, 제품 ID로 정렬해 결과를 안정적으로 유지한다(구현 기본값).
- 집계가 없는 음료를 인기 순위에 임의로 채우지 않는다.

## 개인정보와 권한
공개되는 정보는 제품별 순위·집계 수치뿐이다. 비공개 후기의 내용·별점·닉네임·사용자 ID·개별 작성 시각은 반환하지 않는다. 집계용 DB 함수는 제한된 결과만 제공하며 기존 후기 RLS와 공개 평균 별점 기준은 유지한다. 기록 화면 및 개인정보 안내에 비공개 기록의 통계 포함과 최대 5분 반영 지연을 명시한다.

## 접근 방식
기존 도감 페이지를 검색으로 분리하고 홈에 두 섹션을 구성하는 방식을 선택했다. 인기의 좋아요·조회수 방식은 논의 후 사용자가 음료 기록 기준으로 변경했다. 공개 기록만 집계하는 방안도 논의했으나 사용자는 비공개 포함을 선택했다. 신메뉴 자동 수집 대신 공식 정보를 검수한 수동 등록으로 시작한다.

## 구현과 배포 경계
새 집계 함수와 인덱스가 필요하므로 Supabase 마이그레이션을 준비한다. 현재 원격 DB 자격 증명이 작업 환경에 없으므로 운영 적용은 사용자가 SQL Editor에서 실행하도록 안내한다. 설정 전에는 홈 전체를 오류로 만들지 않고 인기 집계 준비 중을 표시한다. 비공개 원문 비노출·반복 사용자 중복 제거·24시간 경계·새 검색 경로·5개 탭·집계 없는 초기 상태를 검증한다.
