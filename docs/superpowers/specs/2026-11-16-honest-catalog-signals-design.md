# 사실과 어긋나는 표시 정리 (신메뉴 만료, 브랜드 수, 가격 정렬)

작성일: 2026-11-16 (한국 시간). 상태: 사용자 승인 완료(2026-11-16). grilling 세션에서 현재 구현을 대조해 정한 결정 1~3이다. 결정 4(주 1회 신고 확인)와 5(카카오 로그인 체크리스트)는 문서 변경으로 따로 처리했다.

## 배경
"확인하지 못한 정보를 있는 것처럼 보이지 않는다"는 원칙과 달리, 지금 화면 세 곳이 실제 데이터보다 많은 것을 말한다. 2026-10-29 출시 메뉴가 11-16에도 "이번주 신메뉴"로 보이고, 데이터가 4개 브랜드뿐인데 "6개 브랜드 탐색"이라고 쓰며, 가격이 하나도 없는데 "가격 낮은 순" 정렬이 있다.

## 1. 신메뉴 30일 만료
- 홈 신메뉴는 공식 출시일로부터 30일까지 보인다. 한국 시간 오늘 기준으로 출시일이 30일보다 이전이면 빠진다(출시 당일이 0일, 30일째까지 노출). 미래 출시는 지금처럼 빠진다.
- 섹션 제목 "이번주 신메뉴"를 "최근 신메뉴"로 바꾼다.
- 모두 만료되면 기존 빈 상태 안내("공식 출시 정보를 확인한 신메뉴를 준비하고 있어요" + 전체 음료 링크)를 그대로 쓴다.
- 검수된 신메뉴 목록 파일(`data/catalog/new-arrivals.json`)은 바꾸지 않는다. 만료는 화면에서만 걸러진다.

## 2. 데이터가 있는 브랜드 수
- 검색 화면 제목 옆 "6개 브랜드 탐색"을 실제로 판매 중 음료가 있는 브랜드 수로 계산한다(현재 데이터 기준 "4개 브랜드 탐색").
- 브랜드 선택지에서 판매 중 음료가 없는 브랜드는 이름 뒤에 "(준비 중)"을 붙인다. 고를 수는 있고, 골랐을 때의 빈 결과 안내는 지금 그대로다.
- 6개 브랜드 목록 자체(설계서의 브랜드 범위)는 바꾸지 않는다.

## 3. 가격 정렬은 가격이 있을 때만
- 판매 중 음료 중 가격이 확인된 것이 하나도 없으면 정렬 선택지에서 "가격 낮은 순"을 숨긴다. 가격이 하나라도 생기면 다시 보인다.
- 주소에 `sort=price`가 남아 있으면(예: 예전 링크) 지금처럼 동작한다. 미제공은 맨 뒤라 결과는 이름순과 같고 화면 오류는 없다.

## 유지
URL 매개변수, 필터 규칙, 정렬 규칙(미제공은 맨 뒤), 신메뉴 검수 규칙, 접근 가능한 이름(기존 테스트가 쓰는 "필터 적용", "정렬 적용" 등), 가독성 기준. DB 변경 없음.

## 검증
- 신메뉴 만료는 오늘 날짜를 넣어 계산하는 순수 함수로 경계(30일째 노출, 31일째 제외)를 확인한다.
- 검색 화면의 브랜드 수·"(준비 중)"·가격 정렬 숨김은 현재 데이터(4개 브랜드, 가격 없음)로 확인한다. 가격이 있는 경우는 현재 데이터로는 화면에서 확인할 수 없다.
- 홈 제목 변경에 맞춰 기존 테스트의 섹션 이름을 고친다.
